# 01 - Guiding Principles

# Purpose

This document serves as the constitutional document of Project Hippocampus. Every product decision, feature, user experience, AI capability, and technical implementation must align with these guiding principles.

---

# Educational Philosophy

Hippocampus is founded on the belief that effective learning is achieved through evidence-based educational strategies rather than passive information consumption.

Artificial intelligence is not the product—it is an educational tool that guides students through personalized, structured, and active learning experiences.

Every design decision should improve conceptual understanding, long-term retention, and clinical reasoning while remaining aligned with established medical education research.

---

# Core Principles

## 1. Learning Before AI
**Statement:** AI exists to improve learning outcomes—not to demonstrate artificial intelligence.

**Software Design Rule:** If removing AI does not negatively affect learning outcomes, AI should not be used for that feature.

## 2. Evidence Before Features
**Statement:** Every feature must be supported by educational research or solve a validated learning problem.

**Software Design Rule:** Every feature must be traceable to educational evidence or a validated user problem.

## 3. Understanding Before Memorization
**Statement:** Students should understand concepts before memorizing them.

**Software Design Rule:** Prioritize conceptual understanding before presenting memorization activities.

## 4. Active Learning Over Passive Consumption
**Statement:** Every study session should require students to retrieve, apply, explain, or reflect—not simply consume information.

**Software Design Rule:** Passive reading should never be the primary learning activity.

## 5. Personalized Learning Journey
**Statement:** Learning experiences should adapt to each student's knowledge, progress, confidence, goals, and available study time.

**Software Design Rule:** The application should continuously personalize the learning path.

## 6. One Guided Learning Flow
**Statement:** Students should never have to decide which learning tool to use next.

**Software Design Rule:** The platform determines the next best learning activity using evidence-based principles.

## 7. Visual Learning First
**Statement:** For inherently visual subjects, prioritize diagrams, images, illustrations, and interactive visualizations over text alone.

**Software Design Rule:** Visual explanations should be the default whenever they improve understanding.

## 8. Transparency and Trust
**Statement:** The platform must communicate uncertainty honestly and never fabricate confidence.

**Software Design Rule:** When confidence is low, the system should acknowledge its limitations.

## 9. Simplicity Without Sacrificing Capability
**Statement:** Powerful functionality should remain behind a simple and distraction-free experience.

**Software Design Rule:** Reduce cognitive overload by exposing only what students need at the current step.

## 10. Privacy by Design
**Statement:** Student learning data and uploaded materials must be handled with strong privacy, security, and data-governance protections.

**Software Design Rule:** Privacy and security are first-class architectural requirements.

# Feature Acceptance Rule

A feature may only enter the Product Requirements Document if it satisfies all of the following:

- Educational Justification
- Student Value
- Technical Feasibility
- Mission Alignment

Otherwise, it belongs in the backlog.

---

# Traceability Rule

Educational Research → Guiding Principle → Product Requirement → Feature Specification → System Design → Implementation

---

# Definition of Success

Project Hippocampus is successful when medical students understand concepts more deeply, retain knowledge longer, and apply what they learn more effectively through evidence-based educational experiences.
